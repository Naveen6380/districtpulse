# AI processing and empty incident diagnostics

## Current local configuration

The supplied `gemini-3.8-flash` credential/model combination returned **HTTP 429 RESOURCE_EXHAUSTED** with quota ID `GenerateRequestsPerDayPerProjectPerModel-FreeTier`, limit **20 requests per model/project/day**, and a provider retry delay. This is a daily quota exhaustion, not a district-selection failure or a password error. Another key in the same project does not create a new quota.

The documented `gemini-3.5-flash-lite` model was tested with the same credential and successfully returned structured output. The local ignored configuration now selects this model. Billing, account access and payment settings were not changed. This is a model selection change within the existing API; quota availability is still enforced by the provider.

## Failure behaviour

- HTTP 429 is parsed into a small, redacted provider-health record. Raw error bodies, API keys and account/project identifiers are not stored in this record.
- The retry time and daily/rate-limit reason are persisted per configured model.
- Further requests are blocked locally until that time; quota failures are not retried three times per article.
- A quota exception stops the article batch after the affected record. Remaining NEW articles stay pending.
- Failed articles retain their processing error and can be retried after the provider becomes available. Successful records are not regenerated by Retry failed.
- Source evidence validation still applies. A successful HTTP response is not sufficient to create an incident: JSON, relevance and evidence checks must pass.
- Price lists and irrelevant snippets may be processed and excluded without creating incidents. No fictional incidents are inserted to populate a page.

## Incident page

An empty incident array now displays **No incidents extracted yet**, rather than the generic district-empty message. Collector/admin users can see collected/processed/pending/failed article counts and the current provider-block reason/retry time. Department officers see only an assignment-specific empty message; district-wide pipeline diagnostics are protected by backend roles.

`GET /api/districts/{districtId}/news/status` returns counts for the last 30 calendar days, including `excluded` records, and safe provider state. It does not expose raw provider responses, keys or article bodies.

## Useful commands

- `run-news-pipeline.ps1 -Start`: collect/process/group using a background job.
- `run-news-pipeline.ps1 -Retry`: retry FAILED records and continue pending records.
- `run-news-pipeline.ps1`: inspect the stored job and current counts.
- `diagnose-ai.ps1`: one diagnostic generation request; prints schema/quota metadata only. It consumes a request if the provider accepts it.

Do not repeatedly run diagnostics when a known daily quota is exhausted. Check the provider's returned retry time and active limits instead.
